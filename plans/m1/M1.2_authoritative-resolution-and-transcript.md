# M1.2 — Authoritative Resolution and Transcript v1

- **Status:** Planned — activate only after M1.1 acceptance
- **Milestone:** M1 — Battle Laboratory: Deterministic Melee Vertical Slice
- **Dependencies:** M1.1 accepted
- **Authority:** `DESIGN.md` §§11–13, 20, 24–25; `plans/implementation_plan.md` §§4–5, 10 (M1.4–M1.8), 23–24; `deterministic-battle-authority` skill

## Objective

Resolve the committed M1 fixture through one bounded fixed-tick, formation-first authoritative simulator and produce a versioned `BattleResult` plus presentation-sufficient transcript. The resolver runs with no Godot presentation dependency and is the only source of outcome truth later consumed by skip and watch.

## Relevant authoritative context

- Auto-resolve and watched playback are one pre-resolved battle; the transcript communicates authoritative decisions rather than asking the viewer to rerun combat logic.
- M1 needs advance, contact, simple cooldown melee, integer damage, deaths, formation morale loss, rout, terminal result, semantic events, and periodic formation keyframes.
- Exact final morale formula and tick rate are deliberately unresolved. M1 may use its documented fixture rule and starting tick setting without promoting either to final balance/design.

## Required behaviour

1. Implement one public authoritative resolution entry point that accepts only a validated immutable `BattleDefinition`, initializes ordered mutable simulation state internally, advances fixed logical ticks, and returns a resolution containing `BattleResult` and `BattleTranscript`.
2. Move the two M1 formation anchors toward their committed advance destinations in integer X/Z steps. Detect contact using authoritative formation footprints/ranges only; do not inspect transforms, Sprite3D overlap, physics bodies, or render frames.
3. Establish deterministic formation contact and deterministic front-rank attacker/defender pairing. Apply cooldown-based integer melee attacks; record attack and damage even when the fixture produces no casualty on a particular hit.
4. Mark killed units inactive, remove them from active combat roles, and deterministically reform remaining active members into valid slots. Apply a documented fixture casualty-to-formation-morale rule; threshold crossing starts rout, and a routed formation moves away from engagement/deployment centre until terminal logic resolves the battle.
5. Bound all execution with a documented maximum tick count. A non-completing fixture must return an explicit non-terminal/failure result with diagnostic reason and terminal tick information rather than hang or silently declare a winner.
6. Define transcript v1 with header identity/version/seed, ordered semantic events, and periodic formation anchor/facing plus member alive/slot state sufficient for M1 presentation. Required event families: battle started, movement/keyframe state, contact started/ended where applicable, attack resolved, damage dealt, unit killed, morale changed, rout started, and battle ended.
7. Define `BattleResult` with winner/result type, terminal tick, ordered survivors, ordered casualties, routed/retreated state distinct from dead state, commander status if the M1 model contains commanders, and deterministic digest. The digest must include only canonical ordered authoritative data defined by the result/transcript contract.
8. Support debug serialization of transcript/result to an ignored artifact path for inspection, while allowing subsequent runtime playback to consume the same in-memory transcript. Do not build replay persistence/compression infrastructure.

## Architectural constraints and invariants

- Simulation must have no dependency on Godot Node lifecycle, scene tree, camera, input, render FPS, physics, visual assets, or playback state.
- One resolution path only. Do not add army-score shortcut, auto-resolve formula, viewer-side combat decision path, or a second test resolver.
- Iterate in stable ID/list order; tie breaks and RNG state must be explicit and reproducible.
- Use formation-level movement/contact. Do not add per-soldier broad target searches, NavMesh/A*, physics collision, or generalized spatial systems.
- Semantic events/keyframes are authoritative records. Playback will interpolate/present them but may not infer omitted outcome decisions by rerunning logic.
- Keep transcript data inspectable and correctness-first; do not optimize density, add arbitrary replay seeking, or introduce final persistence policy.

- `src/Battle/Transcript/` for transcript/result/event/keyframe/digest types and debug serialization.
- `src/Battle/Model/` for M1.1 model integration only as required.

- Ignored `artifacts/local/m1/` for optional inspected transcript/result output.

## Required verification

### Pure deterministic tests — required

- repeated same fixture/seed/version resolution returns byte-for-byte equivalent canonical result/transcript digest and ordered result records;
- a changed authoritative seed or documented fixture stat produces a changed outcome/event stream or digest for a stated reason;
- advance/contact occurs before melee; damage/casualties/morale/rout/terminal event ordering is internally valid;
- killed/routed members are absent from later active combat pairing and result classifications remain distinct;
- terminal safety cap produces the explicit non-terminal result rather than hanging;
- resolution completes without creating or referencing Godot presentation nodes;
- transcript contains sufficient ordered keyframes/events for all M1 visual states and serializes/deserializes as the same debug data if serialization is added.

### Project regression — required

- Run root build and focused test project via the frozen M0 toolchain paths; inspect output.
- Run the existing frozen BootstrapLab direct acceptance/verifier regression with ignored artifacts and clean report/log. This is an infrastructure regression only; M1 runtime proof remains M1.3+.

## Acceptance criteria

- The one M1 fixture resolves from a committed definition to a bounded terminal result without any Godot presentation dependency.
- Same seed/version/definition repeats are deterministic, including event ordering and digest; no test updates an expected digest without an inspected, documented intentional reason.
- Transcript v1 contains required header, semantic events, and formation/member state sufficient for future playback without re-running combat decisions.
- Result separates survivors, casualties, and routed/retreated state and provides terminal tick/result/digest.
- Safety-cap failure is explicit and test-covered.
- Focused tests, build, and BootstrapLab regression pass with clean inspected evidence; no generated artifacts are tracked.
- `worklog.md` records implemented behaviour, result/digest evidence, and the provisional M1 fixture rule limitations.

## Non-goals

- Godot BattleLab scene, Sprite3D presentation, UI/HUD, playback clock/controls, runtime acceptance report, skip/watch integration, Windows M1 export proof.
- Multiple squads/formation types, target-priority engine, ranged/projectiles, abilities, final morale, commander influence, terrain, content system, campaign effects, replay persistence/compression.

## Escalation conditions

Return to Planner if achieving deterministic termination requires deciding final morale/balance/doctrine rules, if the fixture cannot produce all required M1 state transitions without an undocumented second resolver, or if a proposed transcript cannot support playback without recomputing authoritative outcomes.
