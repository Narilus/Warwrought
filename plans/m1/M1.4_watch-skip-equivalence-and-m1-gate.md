# M1.4 — Watch/Skip Equivalence and M1 Gate

- **Status:** Planned — activate only after M1.3 acceptance
- **Milestone:** M1 — Battle Laboratory: Deterministic Melee Vertical Slice
- **Dependencies:** M1.3 accepted
- **Authority:** `DESIGN.md` §§2, 4, 11–12, 15, 20, 24–25; `plans/implementation_plan.md` §§2, 6, 10 (M1.12–M1.13), 24, 26; `deterministic-battle-authority` and `godot-project-operations` skills

## Objective

Prove the M1 defining promise end-to-end: one committed fixture is authoritatively resolved once, skip consumes its stored `BattleResult` without playback, watch consumes the matching stored transcript in production BattleLab, and both expose exactly the same campaign-relevant outcome and digest. Complete the direct/runtime/exported-player acceptance evidence required for independent M1 review.

## Relevant authoritative context

- “Auto-resolve” means skip visual playback; it is never a simplified battle score. A watched battle is already determined before the viewer begins.
- M1 gate requires deterministic repeatability, headless resolution substantially faster than watched playback, direct BattleLab evidence with visible event presentation, equality of skip/watch outcomes, clean logs, and exported Windows player proof.
- M0 froze the supported build/test/Godot/export/player workflow. M1 may use the same direct commands for a BattleLab scenario but must not redesign M0's block or create a wrapper/runner/polling system.

## Required behaviour

1. Define a narrow committed-resolution handoff used by both M1 paths. The acceptance fixture must invoke the authoritative resolver once per commitment, retain its `BattleResult` and transcript together, and make both skip and watch consume that stored resolution rather than re-resolving or calculating alternate outcomes.
2. Implement/complete `Skip to Result` for the fixture as a data-path operation that returns/applies the stored authoritative result without instantiating playback presentation nodes.
3. Implement/complete the watched handoff so BattleLab receives the same stored transcript/result, reaches transcript end through its playback controller, and exposes the result it presented. It must not compare by display text or infer survivors/casualties from remaining Sprite3D nodes.
4. Add exact equality checks over winner/result type, terminal tick, ordered survivor records, ordered casualty records, routed/retreated state, commander status where applicable, and digest. Both paths must refer to the same committed resolution identity.
5. Extend BattleLab acceptance report only as needed to include skip digest/result, watched digest/result, equality outcome, headless resolution elapsed milliseconds, nominal 1x transcript duration milliseconds, and existing M1.3 observed presentation counters. Report creation remains runtime-owned by the production scene.
6. Add deterministic test fixture coverage proving repeated simulation stability and result independence from playback invocation/control speed. Do not set/update a golden digest without inspecting and documenting why a deliberate authoritative change requires it.
7. Execute the M1 final runtime path directly and in a newly exported Windows player. Use separate ignored per-run artifact roots, explicit logs/reports, the pinned Godot executable/templates, direct official export, and `Start-Process -PassThru -Wait` for the newly exported executable before player report/log verification.

## Architectural constraints and invariants

- One resolver and one committed result/transcript pair only. Any `Skip`/`Watch` helper is a consumer of that pair, not an alternate combat implementation.
- Campaign consequence application is not built in M1. “Apply” here means expose/return the authoritative result at the battle-lab boundary; M9 owns campaign state transition.
- Playback speed, pause/resume, frame rate, camera, visual node count, and visible effects cannot affect equality or digest.
- Do not create new command wrappers, acceptance runners, polling, export presets, player launch substitutes, custom verification architecture, or change the frozen M0 contract. Reuse the transparent existing verifier and direct CLI/player patterns.
- Do not add M2 terrain/scale or M3 doctrine/ranged/ability/multi-squad systems to make this fixture more impressive.

## Required verification

### Pure deterministic tests — required

- run the same committed fixture repeatedly and assert stable result/transcript digest;
- prove skip consumes result without presentation construction and watch consumes the matching stored resolution; assert all required fields equal;
- run playback at 1x, accelerated, and with pause/resume against the same stored transcript and assert unchanged result/digest;
- retain targeted negative/safety coverage from M1.1/M1.2 and existing M0 tests.

### Direct production runtime — required

- From a fresh ignored M1 artifact root, run root build and focused test project through the frozen toolchain.
- Directly launch `BattleLab.tscn` in `battlelab.m1.melee` acceptance mode using the pinned console executable, explicit log/report paths, then run the existing transparent verifier.
- Inspect the runtime-owned report/log: require scenario/scene identity, passing/zero-error core fields, expected non-zero presentation counters, watch/skip equality, and matching non-empty digest. Require measured headless resolve time to be less than one fifth of nominal 1x transcript duration for this fixture; this is an M1 fixture proof, not a final performance budget.

### Exported Windows runtime — required

- Using the same direct M0 export/player pattern and pinned templates, export `Windows Desktop` to a fresh M1 root and verify same-run `.exe`, `.pck`, and required managed dependencies before launch.
- Launch that exact newly exported `Warwrought.exe` with `battlelab.m1.melee`, explicit player log/report, and `Start-Process -PassThru -Wait`; require player exit 0 and finalized evidence before running the existing verifier.
- Inspect player report/log and require the same battle identity, pass/zero-error status, exact expected digest, watch/skip equality, and clean log. Do not treat an editor result or a copied report as player proof.

## Acceptance criteria

- One committed M1 fixture resolution feeds skip and watch; no alternate resolver/score is present.
- Skip and watch exactly agree on all required campaign-relevant fields and digest, both in pure tests and production runtime report.
- Same definition/seed/version repeats deterministically; playback invocation, speed, pause, and visible frame timing do not alter the result.
- Headless M1 fixture resolution completes at least five times faster than its nominal watched 1x transcript duration, with both measurements reported from actual resolution/playback data.
- Direct BattleLab acceptance, transparent verifier, build, and focused tests pass with clean logs and runtime-owned evidence.
- Newly exported Windows player runs the same BattleLab scenario successfully and produces matching clean runtime evidence after `-Wait` completion.
- Artifact hygiene is preserved; no source of truth, verifier semantics, frozen M0 command block, preset, wrapper, polling system, M2/M3 work, or unrelated feature is changed to manufacture the pass.
- `worklog.md` records commands, reports/digests, result equivalence, timing evidence, known fixture limitations, and readiness for independent M1 review.

## Non-goals

- Campaign conflict/ownership/casualty application, M9 transitions, saved battles, long-term replay retention, post-battle analysis UI.
- Procedural terrain/foliage/scale, multiple squads/formations, doctrine, ranged/abilities/commanders beyond M1 fixture records, content/factions/AI.
- CI, new runners/wrappers, test frameworks, export changes, performance optimization beyond proving the architectural headless-vs-playback property.

## Escalation conditions

Return to Planner if skip/watch cannot share the same stored resolution, if runtime/export acceptance needs undocumented setup outside established direct commands, if performance proof exposes a genuine architectural rendering dependency, or if a task change would require deciding M2/M3+ design or weakening protected acceptance.
