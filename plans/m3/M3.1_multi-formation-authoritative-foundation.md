## Objective

Replace M1's exactly-two-formation duel assumption with a deterministic, formation-first authoritative foundation that resolves a fixture containing **at least three squads/formations per side**. Each formation must retain independent anchor, members/slots, provisional target identity, contact relationship, morale, rout/retreat state, and transcript keyframes, while skip and watch consume the same retained resolution.

This proves structural multi-formation authority. It does not choose the final M3 doctrine surface.

## Current hard-coded constraints to remove

- `BattleDefinition` validates exactly two sides **and exactly one squad per side** despite already storing ordered squad lists.
- `AuthoritativeBattleResolver` collects all squad states but uses one global contact flag, `_formations[0]`/`_formations[1]` for contact/melee/axis/terminal logic, and one two-way front-rank pairing.
- `BattlePlaybackController` generically reads unit/squad keyframes but rejects any start state other than exactly two keyframes.
- `BattleLab` report counts read `Squads[0]` instead of side totals.

Do not broaden scope beyond these structural restrictions and the narrow report/verifier/fixture changes needed to prove the new production path.

## Required behaviour

1. Keep the immutable `BattleDefinition -> CommittedBattleResolution.Commit -> AuthoritativeBattleResolver.Resolve -> retained BattleResolution` lifecycle. No second resolver, score-based result, replay decision logic, Godot state, frame timing, physics, or presentation state may influence outcomes.
2. Permit an ordered committed side to contain at least three valid squads. Preserve stable side/squad/member ordering, immutable input copying, rectangular member/slot validation, deterministic canonical-digest ordering, and the existing two-side battle boundary. Do not change the current simulation version or the canonical M1 fixture definition/digests in this slice.
3. Add a new deterministic fixture with three non-overlapping left/centre/right formations per side, stable squad/unit IDs, independent anchors/deployments, and existing rectangular member/slot behaviour. It may reuse existing fixture infantry statistics and `AdvanceOrder`; it must be a new fixture identity, not a rewrite of M1 goldens.
4. Give every active formation an independent current opposing formation relationship. For M3.1 only, the fixture may use a clearly named provisional deterministic pairing rule based on stable squad order/fixture identity. It must not become a public stance, target-priority menu, general candidate scorer, or final doctrine policy.
5. Replace global contact with deterministic formation-pair contact state. Matched contacts may start simultaneously or at different ticks; each emits the correct side/squad/other-side/other-squad identity and may end independently. Melee must resolve only against that formation's current paired opponent through the existing fixed-tick, integer range/cooldown/damage path.
6. Keep casualty handling, reformation, morale, routing, and retreat formation-local. Aggregate terminal outcome by side only after all relevant formations reach resolved states; do not allow one routed formation to overwrite another formation's contact, target, morale, or member state. The existing M1 morale formula remains fixture behaviour only; do not refine it here.
7. Emit ordered semantic events and keyframes for every formation. Retain the current transcript contract and reason codes where applicable; add only the smallest explicit reason/event data needed to identify formation-pair contact/target state. Playback must consume these records without re-running target or combat decisions.
8. Generalize production `BattleLab` startup/report wiring so arbitrary valid tick-zero formation keyframes spawn through the existing centralized `BattlePlaybackController`. Preserve Sprite3D/FixedY terrain projection, foliage, camera, effects, HUD controls, and presentation ownership. Runtime evidence must aggregate side/unit/formation counts rather than assume `Squads[0]`.
9. Do not add a spatial index for this slice. Six fixture formations and three stable declared pairs must use simple stable iteration; record a planner escalation only if implementation evidence demonstrates that this small path cannot remain simple.
